# Интерактивный технологический радар «Будущее 2.0»

Это интерактивная версия техрадара из [`Task3/task3.md`](../task3.md), собранная на [AOE Technology Radar](https://github.com/AOEpeople/aoe_technology_radar). В радаре отражены существующие технологии компании, целевой стек и практики переходного периода. В карточке каждой технологии указаны бизнес-сценарии, причина выбора кольца и правило использования.

## Кольца

- **Adopt — используем:** стандарт для новой разработки.
- **Trial — проверяем пилотом:** целевой кандидат, который должен подтвердить производительность, надёжность и стоимость.
- **Assess — изучаем:** внедряется только после появления измеримого бизнес-кейса.
- **Hold — не расширяем:** существующая зависимость замораживается и постепенно выводится.

## Локальный запуск

В учебном примере используются Node.js 23.7.0 и npm 10.9.2. Версия Node зафиксирована в `.nvmrc`.

```bash
cd Task3/tech_radar
nvm use
npm ci
npm run serve
```

После запуска радар доступен по адресу <http://localhost:3000>.

Если `nvm` не установлен, достаточно совместимой версии Node.js и команд:

```bash
cd Task3/tech_radar
npm ci
npm run serve
```

## Сборка

```bash
cd Task3/tech_radar
npm ci
npm run build
```

Статическая сборка создаётся в `build/`. Директория сборки, `node_modules/`, внутренний кеш `.techradar/` и локальные логи добавлены в корневой `.gitignore`: они восстанавливаются командами выше и не должны попадать в pull request.

AOE Technology Radar 4.4.0 выбран для совместимости с учебным примером. Перед публикацией радара в открытый production нужно отдельно проверить `npm audit` и возможность обновления пакета: его внутренний frontend-стек старше текущих версий. Для локальной демонстрации используется статическая сборка.

## Как обновлять радар

Текущая версия лежит в `radar/2026-08-16`. Для следующего архитектурного пересмотра нужно:

1. Создать в `radar` директорию с новой датой в формате `YYYY-MM-DD`.
2. Добавить Markdown-файлы пересмотренных технологий, не удаляя предыдущую историю.
3. Указать в front matter название, кольцо, квадрант и теги.
4. Запустить `npm run build` и проверить карточки через `npm run serve`.

Пример карточки:

```markdown
---
title: "Apache Iceberg"
ring: trial
quadrant: platforms-and-operations
tags: [new, BS1, BS2, storage]
---

Краткое решение, поддерживаемые бизнес-сценарии и критерии перехода в Adopt.
```

Идентификаторы колец и квадрантов определены в `config.json`. Теги `BS1`–`BS6` соответствуют сценариям из третьего задания.
