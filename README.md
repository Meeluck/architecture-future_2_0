# «Будущее 2.0» — проектирование целевой архитектуры

Решение проектной работы по трансформации IT-ландшафта компании «Будущее 2.0». Цель проекта — спроектировать облачную платформу данных и портал самообслуживания, обеспечить независимое развитие бизнес-доменов и подготовить план перехода от легаси-DWH.

Полное описание кейса и общие требования: [description.md](./description.md).

## Краткое содержание решения

### Task 1. Целевая архитектура

Предложена общая облачная платформа данных с доменными data products, изолированными рабочими областями, каталогом, семантическим слоем и порталом самообслуживания. Легаси SQL Server 2008 временно сохраняется только как система учёта и источник CDC/batch. Проблемы связаны с бизнес-сценариями и приоритизированы по MoSCoW.

### Task 2. Домены и потоки данных

Выделены домены клиента и согласий, клинической деятельности, медицинского ИИ, финтеха, фармы, медицинского оборудования и корпоративного управления. Операционные обмены и публикация аналитических data products показаны на двух согласованных DFD.

### Task 3. Технологический радар и роадмап

Текущие и целевые технологии распределены по кольцам Adopt, Trial, Assess и Hold и привязаны к бизнес-сценариям. Роадмап охватывает 12 месяцев: от согласования доменных границ и создания безопасного облачного фундамента до production-запуска портала и управляемой миграции отчётов.

### Task 4. Terraform

Подготовлен и проверен учебный IaaS-стенд в Yandex Cloud: VPC, подсеть, Security Group, VM, загрузочный и дополнительный диски, а также динамический NAT. В каталоге находятся обязательные Terraform-файлы, диаграмма автоматизации, обоснование конфигурации, журнал выполнения и скриншот успешного `terraform apply`.
